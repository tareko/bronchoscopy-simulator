# Anatomy assets and the CT pipeline

## The bundled tree

`assets/anatomy/generic_adult.json` is generated by
`tools/gen_anatomy/generate_generic_tree.py` — synthetic, deterministic (seeded),
and free of patient data. It contains:

- 85 centreline segments: oral route, trachea, main bronchi, lobar bronchi,
  the 18 numbered bronchopulmonary segments, and procedurally fanned
  subsegmental branches;
- per segment: `label`, `name`, `level`, `parent`, `start_mm`, `position_mm`,
  `direction`, `length_mm`, `radius_mm`, `depth_mm`, `scored`, `landmark`;
- cumulative `depth_mm` from the incisors (carina at 245 mm by construction).

Dimensions are **illustrative**, assembled from typical adult values. They are
not a normative table: the evidence review found no reliable published set of
"cm from the incisors" per segment (wide spread, small samples), so we do not
present ours as standards. Clinicians overriding them is a supported workflow.

### Regenerating and varying

```bash
python3 tools/gen_anatomy/generate_generic_tree.py --out assets/anatomy/generic_adult.json
python3 tools/gen_anatomy/generate_generic_tree.py --out assets/anatomy/variant_b.json --seed 771
```

Different seeds change subsegmental fan-out and branch angles. The generator
asserts laterality, depth monotonicity and scope reachability, so a bad edit
fails loudly.

Anatomical **variety** is the one design feature with a positive RCT behind it
(see docs/01), so shipping several labelled variants is a priority, with
CT-derived cases as the real answer.

## JSON schema (`bronchsim.airway_tree/1`)

```json
{
  "schema": "bronchsim.airway_tree/1",
  "name": "generic_adult",
  "units": "mm",
  "axis_convention": "+X subject left, +Y superior, +Z anterior",
  "provenance": { "kind": "synthetic", "note": "…" },
  "tree": [
    {
      "id": "RB6", "label": "RB6", "level": "segmental", "parent": "RLL",
      "start_mm": [10.2, -283.1, -8.8], "position_mm": [18.4, -292.6, -12.1],
      "radius_mm": 3.25, "depth_mm": 309.0, "scored": true
    }
  ]
}
```

The engine needs only `label`, `parent`, `start_mm`, `position_mm`, `radius_mm`,
`depth_mm` and `scored`. Anything else is metadata that survives a round trip.

## CT pipeline (designed, not yet implemented)

Goal: turn a de-identified chest CT into the same labelled graph, so real patient
anatomy becomes a case.

```
DICOM series
  │  3D Slicer (Linux) + TotalSegmentator "lung_vessels" task (Apache-2.0,
  │  emits lung_airways among other structures)
  ▼
airway mask (NIfTI)
  │  skeletonise (scikit-image / Slicer's "Extract Skeleton"), prune spurs
  ▼
skeleton graph (nodes, edges, radii via distance transform)
  │  label: automatic assignment by lobar/segmental rule + a clinician pass
  │  in Slicer (markup points on each segment); store the mapping
  ▼
airway_tree JSON  ──►  assets/anatomy/<case>.json (+ provenance block)
```

Implementation plan (`tools/ct_pipeline/`):

1. `dicom_to_mask.py` — Slicer headless script, calls TotalSegmentator.
2. `skeleton_to_graph.py` — skeleton, spur pruning, radius from EDT.
3. `label_graph.py` — rule-based initial labels; writes a Slicer markup file for
   clinician correction.
4. `export_tree.py` — schema validation plus laterality/depth assertions copied
   from the generator's checks.
5. `make_preview.py` — renders the tree and mesh to PNG for review.

Quality gates for any CT-derived tree: 18 segments resolvable to depth ≥ 30 cm,
no segment with radius < 1.5 mm (subsegmental pruning), laterality correct, and a
clinician signs off the labels.

## Licence map (this is the sharpest trap)

| Source | Licence | Usable? |
| --- | --- | --- |
| BodyParts3D | CC BY-SA 2.1 JP | share-alike: only as a **separate asset pack**, never merged into MIT code |
| AnatomyStandard | CC BY-NC | **no** — incompatible with this project |
| Zygote | commercial | no |
| NIH 3D Print Exchange | per-entry | case by case |
| LIDC-IDRI | CC BY 3.0 (with access agreement) | yes, with attribution |
| ATM'22 challenge data | redistribution **prohibited** | no — cannot be committed or shipped |
| TotalSegmentator | Apache-2.0 code/weights | yes, and its `lung_vessels` task yields `lung_airways` |
| BronchSim (browser) | CC BY 4.0 | study/reference, not a dependency |
| Fraxinus | BSD-3 | study for the CT → route → virtual bronchoscopy pipeline |

Rule of thumb: MIT for code, but *check every mesh and mask*. When in doubt,
generate or segment it ourselves and record provenance.

## Data policy

- **No patient data in git, ever.** `.gitignore` excludes DICOM/NIfTI/masks and
  `data/patients/`.
- CT-derived trees ship only when the source dataset licence permits
  redistribution, and carry a provenance block naming the dataset and licence.
- De-identification happens before anything touches this repository (DICOM
  header scrubbing + defacing), using the source dataset's approved procedure.
- Session exports contain no imaging and no names.
